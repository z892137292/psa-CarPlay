## 不能直接覆盖安装

母包与测试包的包名都是 `com.androidplay.app`，但签名证书不同：

- 母包证书 SHA-256：`5dc708aa0ae456b490f7b5ce0460e715559ed9be2067f5a9aa8644595daffd41`
- 测试包证书 SHA-256：`b2377f958e32a9a7ba4a4c8357614206297de66e745b10edfa01956ec826a526`

不能正常直接覆盖，不能以 Android 多用户规避冲突。本交付不要求卸载原版，不提供绕过签名、强制替换系统包或清除数据的指令。
优先在未安装同包名应用的独立测试设备验证；本次也没有改包名制作共存版本。

## 主车机测试前必须具备的数据保护条件

1. 离线保存原始母包，并重新计算 SHA-256 核对。
2. 记录当前实际安装的包版本、签名及安装来源；若当前车机版本不是此母包，不能假定此母包就是完整回退目标。
3. 在设备本来就具备的备份权限/官方恢复能力内，保存应用设置、数据库、已配对设备信息、热点配置及必要的认证缓存。不要把口令和认证材料写入公开日志。
4. 普通 `adb backup` 或界面导出不能自动视为完整备份，可能漏掉 noBackup、设备加密数据或 Android Keystore 中的密钥；文件拷贝也不等于可恢复。
5. 明确验证备份可恢复到原签名、原设备环境。无法保证数据恢复，就停在离线分析/独立设备测试阶段，不在主车机试装。

APK 内认证资产保留不代表所有已安装应用的运行数据均在 APK 中。没有已验证备份时不要卸载、清除数据或重置设备。

## 出现问题时

- 尚未安装：保留报告即可，母包没有改变。
- 独立测试设备：停止测试包，保留故障日志；按该设备既定的快照/恢复流程回到测试前状态。
- 未来在主车机经过另行确认后换装：按事先验证过的完整恢复流程恢复原安装与原签名的数据，不能假设原包能直接覆盖测试包。签名冲突在反向回退时同样存在。
- 发生认证、签名权限、系统兼容错误：停止相应操作，不修改 MFi 或签名检查来绕过。
- 发生焦点循环、重复按键、导航/音频/无线退化：停止测试，记录切换步骤及 PSA-MEDIA、media_session、audio 输出。

本次不执行真实设备恢复，也没有验证用户车机的备份与恢复能力。源码回退仅涉及独立修复分支，不需要修改 main、稳定分支或已有 PR #14。
