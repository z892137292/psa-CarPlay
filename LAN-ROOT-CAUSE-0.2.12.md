# Evidence and outstanding verification

Reference WinPlay commit: 5d7d964286c912fb2d41d84683daa6000dae016b. Reviewed networkMode.ts, discovery.ts, iap.ts, run.ts, handoffRecovery.ts, connection-settings.cjs and wlan-reader.cjs. Baseline is complete PSA 0.2.11, still reconstructed on pinned DiPlay 3e43e25c55921bdf5149f5f92851acf202ed353a.

Confirmed in source: JmDNS cold-probe/announcement scheduling creates an approximately five-second publication barrier. 0.2.11 already adapts LAN probe scheduling while checking actual announcement. Duplicate Android handles must be deduplicated by live interface/address, already covered in 0.2.11. Interface control probes previously exhausted one address family's retry budget before trying the next; now one serial attempt rotates to the alternate route, gated after MFi. This source defect is NOT proven to explain the supplied 27-second trace, which reported connectProbes=0.

Confirmed lifecycle defect: AirPlay close notified the UI only after synchronous media teardown. Early terminal notification now precedes resource teardown, including full TEARDOWN; the active-session and controller-generation checks reject obsolete callbacks. UI home-request timing is logged separately from actual home rendering, so the one-second target remains unverified.

Not proven: IPv6 causes the observed delay, WAN availability causes failure, router multicast/AP isolation, phone address ordering, and PSA vendor firmware behavior. Both rapid and slow IPv6 connection attempts exist. Packet capture is required to distinguish mDNS A/AAAA selection and TCP SYN/retry/reachability. BSSID is an AP identifier, not a bandwidth optimization. Missing AP MAC uses the receiver identifier fallback with explicit evidence rather than inventing a verified MAC.

Manual hotspot metadata remains explicitly unverified when Android cannot expose it; configured channel is not represented as measured frequency. Android 9 hidden APIs may reject hotspot configuration reads. No independent PSA/router/phone control is available; all physical tests remain pending. Silent loss on Android 9 currently uses OS TCP keepalive defaults; the 10/3/3 tuning is supported only on newer Android. Do not claim fast silent-loss detection on PSA until this gap is resolved.

Hardware matrix: USB; existing Android hotspot; LAN WAN on/off on the same AP/channel44/40MHz; IPv4 experiment vs dual stack; phone disconnect/Wi-Fi off; car Wi-Fi off; FIN/RST/full TEARDOWN; idle/static screen; short network interruption; reconnect five times. Record event timestamp, home request and visible-home timestamp, first TCP/frame, P50/P95 over ten attempts. Verify no P2P/hotspot creation, no Bluetooth-handoff false disconnect, no WAN false disconnect, and no new controller while prior teardown is blocked.
